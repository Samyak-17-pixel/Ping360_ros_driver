# Ping360 ROS 2 driver

This repository is a **ROS 2 Humble** stack for the **Blue Robotics Ping360** scanning imaging sonar. It talks to the device over **USB serial**, implements the **Ping binary protocol in Python** (no `brping` library), publishes a full set of ROS topics, can **record rosbag2** files via services, and ships **two browser UIs**:


| UI                        | URL (defaults)                                 | What it is                                                               |
| ------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------ |
| **FastAPI GUI**           | [http://127.0.0.1:8080](http://127.0.0.1:8080) | Login, WebSocket **proxy** to rosbridge, polar / CLAHE / histogram views |
| **Static topic explorer** | [http://127.0.0.1:8765](http://127.0.0.1:8765) | Lightweight HTML + roslibjs, talks **directly** to rosbridge             |
| **rosbridge**             | ws://127.0.0.1:9090                            | ROS graph over WebSocket (required for live plots)                       |


**License:** Apache-2.0 (`LICENSE`).  
**Colcon workspace:** `ros2_ws/` (packages live in `ros2_ws/src/`).  
**This file** is the single usage and file-by-file reference for the whole folder.

## 1. What you get

Two ROS 2 packages:


| Package              | Path                         | Role                                                                    |
| -------------------- | ---------------------------- | ----------------------------------------------------------------------- |
| `**ping360_msgs`**   | `ros2_ws/src/ping360_msgs`   | Interface package: `.msg` and `.srv` generated by `rosidl`              |
| `**ping360_driver**` | `ros2_ws/src/ping360_driver` | Python nodes, protocol, launch, YAML config, FastAPI GUI, static `web/` |


Executables after a successful build:


| Executable              | Node name (typical) | Purpose                                      |
| ----------------------- | ------------------- | -------------------------------------------- |
| `ping360_driver_node`   | `ping360_driver`    | Serial I/O, Ping parse, publish `/ping360/*` |
| `ping360_recorder_node` | `ping360_recorder`  | Services to start/stop `ros2 bag record`     |
| `ping360_gui`           | `ping360_gui`       | Uvicorn + FastAPI viewer on port **8080**    |


Launch files:


| File                         | Starts                                                                    |
| ---------------------------- | ------------------------------------------------------------------------- |
| `ping360_bringup.launch.py`  | Driver + recorder + rosapi + rosbridge (if installed) + GUI + static HTTP |
| `ping360_web_only.launch.py` | Same UIs **without** serial driver (for `ros2 bag play`)                  |

## 2. How data flows

```text
┌─────────────┐   USB UART    ┌──────────────────────────┐
│  Ping360    │◄─────────────►│  ping360_driver_node     │
│  (auto_tx)  │               │  ping_protocol.py parse  │
└─────────────┘               └────────────┬─────────────┘
                                           │ /ping360/*
                    ┌──────────────────────┼──────────────────────┐
                    ▼                      ▼                      ▼
            scan_image (Image)     auto_device_data         status (1 Hz)
            derived                device_information       protocol_version
                    │
                    │  rosbridge :9090  +  rosapi
                    ▼
     ┌──────────────────────────────────────────────────────────┐
     │ Browser                                                  │
     │  GUI :8080  FastAPI ──proxy──► rosbridge                 │
     │  Explorer :8765  roslibjs ──direct──► rosbridge          │
     └──────────────────────────────────────────────────────────┘

     ping360_recorder_node ──services──► ros2 bag record
```

The **GUI does not connect the browser straight to the robot’s rosbridge** by default. The browser opens `ws://<this-page-host>/ws/rosbridge`; the Python process then opens a second WebSocket to the rosbridge URL stored in the session (for local use: `ws://127.0.0.1:9090`). That URL must be reachable **from the machine running `ping360_gui`**.

The **static explorer** is the opposite: the browser talks to rosbridge **directly** (default `ws://127.0.0.1:9090`).

### 4.3 `ping360_msgs` — interface package


| File                                   | What it is                                                                                                                                                                                 |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `**package.xml`**                      | ROS package name `ping360_msgs`, `ament_cmake`, `rosidl` generators, depends on `std_msgs` and `builtin_interfaces`. Member of `rosidl_interface_packages`.                                |
| `**CMakeLists.txt**`                   | Lists every `.msg` and `.srv` passed to `rosidl_generate_interfaces`. If you add a message, add it **here** and rebuild `ping360_msgs` then `ping360_driver`.                              |
| `**README.md`**                        | Short pointer: this package is interfaces only.                                                                                                                                            |
| `**msg/Ping360DeviceInformation.msg**` | Ping **id 4**. `device_type` (2 = Ping360), revision, firmware major/minor/patch, reserved. Latched topic `/ping360/device_information`.                                                   |
| `**msg/Ping360ProtocolVersion.msg`**   | Ping **id 5**. Protocol version fields. Latched `/ping360/protocol_version`.                                                                                                               |
| `**msg/Ping360DeviceData.msg`**        | Ping **id 2300** (manual / single ping). Header + mode, gain, angle, timing, frequency, sample count, `uint8[] data`. Topic `/ping360/device_data` (often unused in auto mode).            |
| `**msg/Ping360AutoDeviceData.msg`**    | Ping **id 2301** (auto_transmit). Same idea as device_data plus sweep fields: `start_angle`, `stop_angle`, `num_steps`, `delay_ms`. **Primary stream.** Topic `/ping360/auto_device_data`. |
| `**msg/Ping360Derived.msg`**           | Computed per ping: `angle_rad`, `angle_gradians`, peak bin index/value, `range_to_peak_m`, `speed_of_sound_mps`. Topic `/ping360/derived`.                                                 |
| `**msg/Ping360ScanImageMeta.msg**`     | Companion to `sensor_msgs/Image`: width/height, sweep angles, `samples_per_ping`, `encoding_note` (0 = rows=angle, columns=range). Topic `/ping360/scan_image_meta`.                       |
| `**msg/Ping360Status.msg**`            | 1 Hz health: `connected`, `last_error`, `auto_data_rate_hz`, parse/checksum counters, `last_message_id`. Topic `/ping360/status`. Uses `builtin_interfaces/Time stamp` (not a Header).     |
| `**srv/StartRecording.srv**`           | Request: `output_directory`, `bag_name_prefix`, `topics[]` (empty = default list). Response: `success`, `message`, `bag_path`.                                                             |
| `**srv/StopRecording.srv**`            | Empty request. Response: `success`, `message`.                                                                                                                                             |

## 5. Prerequisites from scratch

Assume **Ubuntu 22.04**.

### 5.1 ROS 2 Humble

Follow the official Humble install, or at minimum:

```bash
sudo apt update
sudo apt install ros-humble-desktop
```

Every new terminal:

```bash
source /opt/ros/humble/setup.bash
```

Optional but required for live browser data:

```bash
sudo apt install ros-humble-rosbridge-suite
```

That provides `rosbridge_server` and is used with `rosapi` (bringup already starts `rosapi_node`).

Serial Python binding:

```bash
sudo apt install python3-serial
```

(`package.xml` already lists `python3-serial` as `exec_depend`.)

Build tools:

```bash
sudo apt install python3-colcon-common-extensions python3-pip
```

### 5.2 FastAPI GUI Python packages (once)

```bash
pip3 install --user -r /home/samyak/Ping360_ros_driver/ros2_ws/src/ping360_driver/gui-requirements.txt
```

Adjust the path if your clone lives elsewhere. Without this, `ping360_gui` will crash on `import fastapi` / `import websockets`.

### 5.3 Dialout (USB serial)

```bash
sudo usermod -aG dialout $USER
```

Log out and back in (or reboot). Confirm:

```bash
groups   # should include dialout
```

## 6. Clone, build, overlay (do this every new terminal)

Replace the path if needed.

```bash
cd /home/samyak/Ping360_ros_driver/ros2_ws
source /opt/ros/humble/setup.bash
colcon build --packages-select ping360_msgs ping360_driver
source install/setup.bash
```

**Always source this workspace’s `install/setup.bash`**, not some other project such as `~/ping360_sonar`. Last overlay wins. If `AMENT_PREFIX_PATH` only lists `ping360_sonar` and Humble, `ros2 launch ping360_driver ...` will fail with **package not found**.

Check:

```bash
ros2 pkg prefix ping360_driver
# expect: .../Ping360_ros_driver/ros2_ws/install/ping360_driver

ros2 pkg executables ping360_driver
# ping360_driver_node, ping360_recorder_node, ping360_gui
```

Rebuild after **any** change to Python, launch, YAML, web files, or messages (`ping360_msgs` first if you changed `.msg`/`.srv`).

## 7. Hardware: serial port and dialout

1. Plug in the Ping360 USB adapter.
2. Find the device:

```bash
ls /dev/ttyUSB* /dev/ttyACM*
dmesg | tail
```

1. If it is not `/dev/ttyUSB0`, pass it at launch:

```bash
ros2 launch ping360_driver ping360_bringup.launch.py serial_port:=/dev/ttyACM0
```

1. Nobody else should hold the port (another driver, `minicom`, old `ping360_sonar` node).

Default baud in this stack is **115200** (`config/ping360_driver.yaml`). Override with `baud_rate:=...` if your adapter/firmware needs something else.

source /opt/ros/humble/setup.bash

ros2 topic echo /ping360/status --once
ros2 topic hz /ping360/auto_device_data
```

Stop the stack with **Ctrl+C** in the launch terminal. The driver tries to send **motor off** on shutdown.

## 9. Use the FastAPI GUI

1. Open **[http://127.0.0.1:8080](http://127.0.0.1:8080)** (use `127.0.0.1`, not a mix of `localhost` and `127.0.0.1`, so cookies stay consistent).
2. Login:
  - **Host:** `127.0.0.1` (same machine as the driver). SSH password **not** required for loopback.
  - **Rosbridge override (optional):** `127.0.0.1:9090` or `ws://127.0.0.1:9090`.
  - Remote Jetson: `user@192.168.x.x` plus SSH password; the **viewer process** must be able to TCP to that rosbridge.
3. Leave **Rosbridge** toggle on. Status should become connected.
4. Topic dropdown: pick `**/ping360/scan_image`** (preferred) or another Ping360-like topic.
5. Tabs: Raw, Polar, Polar TURBO, Rect CLAHE, Bearing peaks, Histogram. FOV / max range / bearing offset interpret image geometry.
6. **Record UI** records the canvas in the browser (mp4/webm), not a rosbag.
7. **Logout** clears the session cookie.

If the page says rosbridge is unreachable, rosbridge is not running, or you pointed the session at a host the **GUI server** cannot reach (classic mistake: `127.0.0.1` meaning the **robot** while the GUI runs on a **laptop**).

## 10. Use the static topic explorer

1. Open **[http://127.0.0.1:8765](http://127.0.0.1:8765)**.
2. Needs **rosbridge** + **rosapi**. The page uses **roslibjs** from a CDN (needs network unless cached).
3. Refresh the topic table; click **View** on `/ping360/scan_image`.
4. URL query:
  - `?topic=/ping360/scan_image`
  - `?ws=ws://127.0.0.1:9090`
5. Recorder fields call `/ping360/recorder/start` and `/stop` (same as CLI).
6. Polar skip bins, CLAHE clip, montage, JSON panel are all on this page.

## 11. Nodes, topics, QoS

### `ping360_driver` (`ping360_driver_node`)


| Topic                         | Type                                 | QoS                                         | Meaning                                 |
| ----------------------------- | ------------------------------------ | ------------------------------------------- | --------------------------------------- |
| `/ping360/auto_device_data`   | `ping360_msgs/Ping360AutoDeviceData` | Sensor: best effort, volatile, depth 10     | One message per auto ping (id **2301**) |
| `/ping360/device_data`        | `Ping360DeviceData`                  | same                                        | id **2300**; rare in auto mode          |
| `/ping360/derived`            | `Ping360Derived`                     | same                                        | Peak bin and range for **this** ping    |
| `/ping360/scan_image`         | `sensor_msgs/Image`                  | same                                        | Accumulated raster, `mono8`             |
| `/ping360/scan_image_meta`    | `Ping360ScanImageMeta`               | same                                        | Dimensions and sweep                    |
| `/ping360/status`             | `Ping360Status`                      | same                                        | **1 Hz** health                         |
| `/ping360/device_information` | `Ping360DeviceInformation`           | Latched: reliable, transient local, depth 1 | id **4**                                |
| `/ping360/protocol_version`   | `Ping360ProtocolVersion`             | Latched                                     | id **5**                                |
| `/tf_static`                  | TF                                   | —                                           | Only if `publish_tf_static` is true     |


Topics are **absolute** (`/ping360/...`), not private `~/`.

### `ping360_recorder`

No subscriptions. Services only (see §16).

## 12. Custom messages and services

Field-level comments live in the `.msg` / `.srv` files. Summary:

- **Angles** on the device are **gradians** (400 gradians = 360°).
- `**data`** on auto/device messages is the echo profile for **one ping** (amplitude vs range bin).
- `**scan_image`** is many pings stacked; it will not match the latest `derived` peak at the same timestamp.
- `**encoding_note = 0**`: image **row** = bearing index, **column** = range bin.

## 13. Driver parameters

Defaults: `ros2_ws/src/ping360_driver/config/ping360_driver.yaml`.


| Parameter                | Default        | Meaning                                                 |
| ------------------------ | -------------- | ------------------------------------------------------- |
| `serial_port`            | `/dev/ttyUSB0` | Device path                                             |
| `baud_rate`              | `115200`       | UART baud                                               |
| `frame_id`               | `ping360_link` | Header / TF child                                       |
| `publish_tf_static`      | `false`        | Publish static TF                                       |
| `tf_parent_frame`        | `base_link`    | TF parent                                               |
| `tf_translation_xyz`     | `[0,0,0]`      | metres                                                  |
| `tf_rotation_rpy_deg`    | `[0,0,0]`      | roll, pitch, yaw **degrees**                            |
| `speed_of_sound_mps`     | `1500.0`       | Used for `range_to_peak_m`                              |
| `device_dst_id`          | `1`            | Ping destination id                                     |
| `gain_setting`           | `1`            | Auto transmit gain                                      |
| `transmit_duration_us`   | `12`           | Pulse length                                            |
| `sample_period_25ns`     | `88`           | Sample period in **25 ns** units (range resolution)     |
| `transmit_frequency_khz` | `740`          | Transmit frequency                                      |
| `number_of_samples`      | `400`          | Range bins = image **width**                            |
| `start_angle_gradians`   | `0`            | Sweep start                                             |
| `stop_angle_gradians`    | `399`          | Sweep stop                                              |
| `num_steps`              | `1`            | Angle increment (gradians)                              |
| `delay_ms`               | `0`            | Inter-ping delay                                        |
| `send_init_break`        | `true`         | Write newline before requests (helps some USB adapters) |

Bringup launch arguments currently overlay `**serial_port`** and `**baud_rate**`. Any parameter can also be set with:

ros2 run ping360_driver ping360_driver_node --ros-args -p serial_port:=/dev/ttyACM0
```

## 14. Scan image, coordinates, range math

- Buffer size: **height × width** = **400 × `number_of_samples`** (default 400×400).
- Incoming auto ping `angle` is in gradians; the driver writes `data` into **row = angle % 400**.
- Image: `encoding=mono8`, `step=width`.

**Column** ↔ range bin. **Row** ↔ bearing (400 gradians = 360°).

For `/ping360/derived`, peak index in that ping’s `data`:


t = \mathrm{peakindex} \times T_{25} \times 25 \times 10^{-9}\ \mathrm{s}



\mathrm{rangetopeakm} = t \times \mathrm{speedofsoundmps} \times 0.5


T_{25} is `sample_period_25ns`. The **0.5** is round-trip. Adjust sound speed for water conditions.

## 21. Troubleshooting


| Symptom                         | What to check                                                                |
| ------------------------------- | ---------------------------------------------------------------------------- |
| Package not found               | Overlay path (§20); rebuild                                                  |
| `ping360_gui` import errors     | `pip3 install --user -r gui-requirements.txt`                                |
| Serial open / permission denied | `dialout`, correct `/dev/ttyUSB*` or `ttyACM*`, nothing else using the port  |
| No `/ping360/*`                 | Device power, baud, `send_init_break`, USB cable; watch driver logs          |
| `checksum_errors` rising        | Noise, cable, baud mismatch                                                  |
| Empty `scan_image`              | Wait for a full rotation; image fills by angle                               |
| GUI disconnected / proxy failed | rosbridge installed and running; session URL reachable **from the GUI host** |
| Explorer loads but no live data | rosbridge + rosapi; CDN scripts; `?ws=` URL; firewall                        |
| Explorer disconnected pill      | Browser cannot open `ws://127.0.0.1:9090`                                    |
| Recorder fails                  | Source ROS in the environment that runs the recorder node                    |
| Two tools fight for USB         | Stop `ping360_sonar` / other serial programs                                 |
| Login cookie weirdness          | Stick to `http://127.0.0.1:8080` not mixed `localhost`                       |
| Nested `Ping360_GUI` confusion  | Use `ping360_driver/gui/` only                                               |


Driver logs to watch: `Serial open`, `Sent protocol request + auto_transmit`, serial retry warnings.

## 22. Security notes

- GUI cookies are **HttpOnly**, `secure=False` (HTTP). Put TLS in front if you expose beyond a trusted LAN.
- SSH passwords are used to **verify** remote login and optional remote bag commands; they are not stored in the signed session as a long-lived password.
- Keep `~/.local/share/ping360_gui/session_secret.bin` private; anyone with it can forge sessions until you delete it (a new secret is created on next start if missing).
- Launch binds the GUI to **127.0.0.1** so it is not advertised on all interfaces. Changing `PING360_VIEWER_HOST` to `0.0.0.0` exposes the login UI on the network.
